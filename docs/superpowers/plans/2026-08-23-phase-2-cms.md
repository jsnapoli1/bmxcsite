# Phase 2: CMS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the camp's content out of hardcoded JavaScript and into D1, so the directors can edit staff, FAQ, merch, and camp facts in the admin panel and see changes live without a deploy.

**Architecture:** Content lives in D1 with an explicit draft → publish step. Publishing writes to D1 and purges a KV cache; the public site reads KV, never D1, so pages stay as fast as the current static bundle and D1 reads stay near zero. Migration is per-area so a bad cutover breaks one page, not the site.

**Tech Stack:** Cloudflare Workers, D1, Workers KV, Hono 4.13, React 19 + Vite 7, Vitest 4.1 + `@cloudflare/vitest-plugin`.

**Spec:** `docs/superpowers/specs/2026-08-22-admin-panel-design.md`

## Global Constraints

- **Node 22** (CI runs 22; wrangler 4 refuses to run on 20).
- ES modules only.
- Permission areas are exactly `blog`, `media`, `merch`, `campinfo`. DB flags exactly `can_blog`, `can_media`, `can_merch`, `can_campinfo`, `is_admin`.
- Every admin route MUST be mounted after `app.use('/api/admin/*', requireAuth)` in `worker/app.js`. A route registered before it is completely ungated — this was verified empirically, not assumed.
- Boolean coercion is strict: only literal `true` sets a flag. Truthiness bugs here previously let a sole admin lock themselves out.
- Timestamps INTEGER Unix seconds via `unixepoch()`, never TEXT.
- **The public site's rendered content must not change during migration.** Each area's cutover must produce identical output to the current hardcoded module.
- Design direction "Field Guide": serif display, warm paper surfaces, **no shadows**, radii 2-6px. Banned: uppercase headings, gradient text, decorative gradients, hover lifts, pill buttons.
- Voice (CLAUDE.md): plain and direct. Avoid em-dash aphorisms, rule-of-three lists, "X, not Y" antithesis. Em-dashes inside quoted FAQ answers are the camp's own words — never rewrite them.
- **CI cannot apply D1 migrations** (`CLOUDFLARE_API_TOKEN` lacks D1:Edit). Every migration must be applied by hand with `npm run migrate:remote` before the deploy that needs it.

## Scope decision, made explicitly

The site has 27 exports across 8 data modules. Not all are equal:

| Module | Exports | Shape | In this phase? |
|---|---|---|---|
| `staff.js` | `STAFF_GROUPS`, `STAFF_CREDENTIALS` | ordered groups → ordered members | **yes** |
| `faq.js` | `FAQ_CATEGORIES` | ordered categories → ordered Q&A | **yes** |
| `merch.js` | `MERCH_ITEMS`, `MERCH_FACTS`, `MERCH_CAVEATS`, `MERCH` | flat lists + a small config | **yes** |
| `camp.js` | `CAMP`, `PILLARS`, `STATS`, `SCHEDULE` | deeply nested config object | **partial — see below** |
| `registration.js` | `PRICE_TIERS`, `KEY_DATES`, `DEPOSIT`, … | dated, changes yearly | no — Phase 2b |
| `videos.js`, `playlists.js`, `packing.js` | lists | stable | no — Phase 3 (media) |

**`CAMP` is deliberately not fully migrated.** It is a deeply nested
configuration object (`venue`, `contact`, `social`, `session`) consumed by
four pages. Flattening it into tables buys nothing — nobody edits
`social.facebook` weekly — and the nesting would make the editor UI worse than
the code it replaces. Instead, this phase migrates the **fields that actually
go stale**: session dates, contact email, contact phone. The rest stays in
code and moves later only if the directors ask.

Rationale worth recording: the goal is that the camp stops needing a developer
for routine edits, not that every constant reaches a database.

- [ ] **Step 3: Write the migration**

Create `migrations/0002_content.sql`:

```sql
-- Content the camp directors edit. Every row carries its own draft/published
-- status so a half-finished edit never reaches the public site.
--
-- FK cascades are declared, but SQLite only enforces them when
-- `PRAGMA foreign_keys = ON`. D1 enables this by default; the schema test
-- asserts the cascade actually fires rather than trusting that.

CREATE TABLE staff_groups (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  title      TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

CREATE TABLE staff_members (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  group_id   INTEGER NOT NULL REFERENCES staff_groups(id) ON DELETE CASCADE,
  name       TEXT NOT NULL,
  role       TEXT,
  bio        TEXT,
  since      INTEGER,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

CREATE TABLE faq_categories (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  slug       TEXT,
  label      TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

CREATE TABLE faq_items (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  category_id INTEGER NOT NULL REFERENCES faq_categories(id) ON DELETE CASCADE,
  question    TEXT NOT NULL,
  answer      TEXT NOT NULL,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  status      TEXT NOT NULL DEFAULT 'draft',
  updated_at  INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by  TEXT
);

CREATE TABLE merch_items (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL,
  detail     TEXT,
  price_low  INTEGER,
  price_high INTEGER,
  image      TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

CREATE TABLE merch_facts (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  title      TEXT NOT NULL,
  body       TEXT NOT NULL,
  tag        TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

-- Only the camp fields that actually go stale year to year. The rest of the
-- CAMP object stays in code deliberately: nobody edits social links weekly,
-- and flattening the nesting would make the editor worse than the code.
CREATE TABLE camp_fields (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,
  label      TEXT NOT NULL,
  status     TEXT NOT NULL DEFAULT 'draft',
  updated_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_by TEXT
);

-- Bumped on every publish. The public cache key includes this number, so a
-- publish invalidates the cache without needing an explicit KV delete to
-- succeed — a failed purge can serve stale content, a version bump cannot.
CREATE TABLE content_version (
  area    TEXT PRIMARY KEY,
  version INTEGER NOT NULL DEFAULT 1
);

INSERT INTO content_version (area, version) VALUES
  ('staff', 1), ('faq', 1), ('merch', 1), ('campinfo', 1);

CREATE INDEX idx_staff_members_group ON staff_members (group_id, sort_order);
CREATE INDEX idx_faq_items_category ON faq_items (category_id, sort_order);
```

## Task 2: Content repository

**Files:**
- Create: `worker/content/repository.js`, `test/worker/repository.test.js`

**Interfaces:**
- Consumes: `env.DB`, Task 1's schema.
- Produces:
  - `getPublished(db, area)` → `Promise<object>` — the published content for an area, shaped exactly like the current JS module's export.
  - `getAll(db, area)` → `Promise<object>` — draft and published, for the editor.
  - `saveArea(db, area, payload, editorEmail)` → `Promise<void>` — replaces an area's rows in one batch, preserving order.
  - `publishArea(db, area, editorEmail)` → `Promise<number>` — flips draft→published, bumps and returns the new version.
  - `getVersion(db, area)` → `Promise<number>`.
- Throws `UnknownAreaError` for an area not in `['staff','faq','merch','campinfo']`.

- [ ] **Step 1: Write the failing test**

Create `test/worker/repository.test.js`:

```js
import { describe, it, expect } from 'vitest';
import { env } from 'cloudflare:test';
import {
  getPublished, getAll, saveArea, publishArea, getVersion, UnknownAreaError,
} from '../../worker/content/repository.js';

const STAFF = {
  groups: [
    { title: 'Camp Directors', members: [
      { name: 'Ken Crawford', role: 'Camp Director', bio: 'Bio.' },
      { name: 'Sarah Schnitter', role: 'Camp Director', bio: 'Bio.' },
    ] },
    { title: 'Veteran Coaches', members: [
      { name: 'Someone Else', role: 'Coach', bio: 'Bio.' },
    ] },
  ],
};

describe('repository', () => {
  it('rejects an unknown area', async () => {
    await expect(getPublished(env.DB, 'billing'))
      .rejects.toBeInstanceOf(UnknownAreaError);
  });

  it('returns empty published content before anything is published', async () => {
    const content = await getPublished(env.DB, 'staff');
    expect(content.groups).toEqual([]);
  });

  it('saves as draft, so nothing is published yet', async () => {
    await saveArea(env.DB, 'staff', STAFF, 'ken@example.com');
    expect((await getPublished(env.DB, 'staff')).groups).toEqual([]);
    expect((await getAll(env.DB, 'staff')).groups).toHaveLength(2);
  });

  it('publishes and preserves group and member order', async () => {
    await saveArea(env.DB, 'staff', STAFF, 'ken@example.com');

  it('bumps the version on publish', async () => {

    await saveArea(env.DB, 'staff', STAFF, 'ken@example.com');
    const after = await publishArea(env.DB, 'staff', 'ken@example.com');

  });

  it('replaces rather than appends on a second save', async () => {
    await saveArea(env.DB, 'staff', STAFF, 'ken@example.com');
    await saveArea(env.DB, 'staff', { groups: [
      { title: 'Only Group', members: [{ name: 'Solo', role: 'Coach', bio: '' }] },

    const { groups } = await getAll(env.DB, 'staff');
    expect(groups).toHaveLength(1);
    expect(groups[0].title).toBe('Only Group');
  });

  it('records who edited', async () => {
    await saveArea(env.DB, 'staff', STAFF, 'sarah@example.com');
    const row = await env.DB.prepare(
      'SELECT updated_by FROM staff_groups LIMIT 1',
    ).first();
    expect(row.updated_by).toBe('sarah@example.com');
  });
});
```

## Task 3: KV cache

**Files:**
- Create: `worker/content/cache.js`, `test/worker/cache.test.js`
- Modify: `wrangler.jsonc`

**Interfaces:**
- Consumes: `env.CONTENT` (KV binding), Task 2's repository.
- Produces:
  - `cachedContent(env, area)` → `Promise<object>` — read-through cache keyed `content:<area>:v<version>`.
  - `purge(env, area)` → `Promise<void>` — best-effort delete of the current key.

The version-in-the-key design is deliberate: a publish bumps the version, so
the next read misses on a NEW key regardless of whether the purge succeeded.
A failed purge wastes a KV entry; it cannot serve stale content.

- [ ] **Step 1: Create the KV namespace**

```bash
npx wrangler kv namespace create CONTENT
```

Copy the returned id into `wrangler.jsonc`:

```jsonc
"kv_namespaces": [
  { "binding": "CONTENT", "id": "<id from the command>" }
]
```

- [ ] **Step 4: Write `worker/content/cache.js`**

- Key is `content:<area>:v<version>`, version from `getVersion`.
- On miss: read from the repository, write to KV with `expirationTtl: 86400`, return the value.

## Task 6: Public pages read from the API

**Files:**
- Create: `src/hooks/useContent.js`, `test/e2e/content-parity.spec.js`
- Modify: `src/pages/Staff.jsx`, `src/pages/Faq.jsx`, `src/pages/Merch.jsx`

**Interfaces:**
- Produces: `useContent(area, fallback)` → `{ content, isLoading }`.

**The fallback is the safety net.** `useContent` takes the bundled module as
its fallback and renders it immediately, then swaps in the API response when
it arrives. If the API is down, slow, or returns an error, the page shows the
current content instead of an empty state. This is what makes the cutover
non-destructive.

- [ ] **Step 1: Write `src/hooks/useContent.js`**

```js
import { useEffect, useState } from 'react';

/**
 * Read published content for an area, falling back to the module bundled at
 * build time.
 *
 * The fallback renders first and is replaced only when a fetch succeeds, so
 * an API outage degrades to the content that shipped with the build rather
 * than to a blank page.
 */
export function useContent(area, fallback) {
  const [content, setContent] = useState(fallback);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    fetch(`/api/content/${area}`)
      .then((res) => (res.ok ? res.json() : Promise.reject(res.status)))
      .then((data) => { if (!cancelled) setContent(data); })
      .catch(() => { /* keep the bundled fallback */ })
      .finally(() => { if (!cancelled) setIsLoading(false); });
    return () => { cancelled = true; };
  }, [area]);

  return { content, isLoading };
}
```
